# 論点を図で示す資料の作り方

- 論点ごとに、言いたいことを1文に決め、下の「選ぶ順」で形を選んで図を先に描き、文章は図ごとの要点1行にする。詳細は畳み、開いた中も図と要点1行で説明する。出す前に、文章を消しても図だけで論点が分かるかを見る（文章を先に書いて図を後から足すと、図の付いた文章の資料になり、読み手が論点をつかめなかったため）。
- 形の一覧は目安で、論点に合わなければほかの形を選ぶ（形を1つの表に固定すると、どの資料も同じ型になるため）。
- ソフトウェアの構成、やりとり、状態、配置の図は、同じリポジトリの plugin「dev-figures」の skill で選ぶ。

## 選ぶ順

1. その論点で言いたいことを1文に決める（例：「A の市場は B の3倍ある」）。
2. その1文が何を比べているかを、下の分類から決める。
3. [references/figures.html](references/figures.html) のその分類の図から形を選ぶ。形から先に決めない。
4. 描き方は、Artifact の側にその形の描き方があればそれを使い、無いときだけ figures.html の見本を写す。Artifact の側とは、Artifact の tool が作れる種類（quickstart と types の一覧に出る Dashboard など）と、その時点の skill の一覧にある Artifact や図の skill（artifact-design、artifact-diagramming、dataviz など）である。直す元の資料に同じ論点の図や操作（スライダー、切り替え）があれば、それも使う。Artifact の側の種類と skill は今後も増え、色、明暗の配色、操作まで整っているので、figures.html で描き直すと劣るため。

この順は Gene Zelazny の Say It With Charts（言いたいこと、比べ方、形の順）による。figures.html には112種の図が、名前、形（何を、どの軸や色や大きさで描くか）、使う場面、最小の svg で並ぶ。名前だけで形が浮かばない図は、その図の `<figure>` を読んで形を写す（ファイル全体は大きいので、名前で探して読む）。見本の svg は形を示すためのもので、描く手段は決めない。

位置の計算が要る図（Sankey、Chord、Network、Contour map、Treemap など）は、作る側で d3 などを動かして位置を計算し、結果を svg に書き出してページに埋め込む。地図は、都道府県の境界のデータ（npm の jpn-atlas など）を簡略化した path にして埋め込む（元の93種を試しに描いたとき、どれもこの方法で描けた。ページを開くたびにライブラリや境界のデータを読み込む方法は試せていない）。

## 分類

数のある論点の9分類と図の名前は Financial Times Visual Vocabulary（MIT）による。

| 分類 | 使う場面 |
|---|---|
| 差 | 0、目標、平均などの基準からの上下 |
| 相関 | 2つ以上の値の関係。因果と読まれやすいので、因果でなければそう書く |
| 順位 | 値そのものより、並びの中の位置が大事なとき |
| 分布 | 値がどこにどれだけあるか、偏り |
| 時間での変化 | 傾向の変わり方。期間の取り方で印象が変わる |
| 内訳 | 全体を部品に分ける。部品の大きさだけが関心なら「大きさ」 |
| 大きさ | 人数、金額などの数えた量の比較（率や割合でなく） |
| 地理 | 場所や地域の違いがほかの何より大事なときだけ |
| 流れ | 2つ以上の状態や場所の間を動く量（お金、患者、情報） |
| 数が無い論点 | 位置づけ、構造と分け方、決まった枠組み（SWOT、7S、キャンバス）、役割の分担、手順と時間、関係、因果、確からしさ、優先と判断、前と後 |

見込みや推計には幅（Fan chart、範囲つきの棒）を描き、1つの値に見せない。

## 文章で落ちる差を描く

大きさは面積か長さ、確からしさは線の種類（実線、点線）、関係の近さは距離、重みは線の太さで描き分ける。文章では同じ重さに並ぶ論点の差が、図では見える。

図の中の文字は、部品の名前と値と数語の注記にする。文を四角に詰めると、図の形をした文章になり、読み手は結局文章を読むことになる。文は図の下の要点1行か、畳んだ詳細に置く。
