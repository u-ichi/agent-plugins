# 名前より先に具体対象と表記を決める

返信、文書、図を書く前に、扱う具体対象と役割を確定し、本文と図で使う候補語を1つにそろえた7列の対応表を別ファイルに保存する。書きながら仮の呼び名、言い換え、数だけの短縮、英語の独自訳を作ることを手順で防ぐ。

## 適用判定

既存文章の対象、役割、名前、意味を変えない表現だけの推敲では、新しい対応表を作らず現在の工程を続ける。

次のいずれかに該当するときに使う。判断に迷う場合は該当扱いにする。

1. 調べた結果の報告、原因の調査報告、仕組みの説明、案の比較、対策案、設計資料、要求からの設計を書く（チャットやスレッドの返信、図を含む）。
2. 新しい名前を決める（ファイル名、公開仕様、状態名、条件名、イベント名、値や記録の型名、メソッド名、boolean 名、画面に出す名称）。依頼に「命名」の語が無くても該当する。
3. ユーザーが示した推論や作業の順序を短い見出しやラベルに要約する。

## 手順

本文と図を書く前に、使う下書きの欄と7列の対応表をこの順で作る。

### 1. 下書きの欄を先に書く

使っている output style やプロジェクト指示に返信前の下書きの欄が定められているときは、その欄を同じ下書きへ先に書き出し、欄に現れる対象もすべて次の手順で作る7列の対応表へ登録する。

下書きの欄が定められていない場合でも、原因の報告や対策の提案を書くときは、対応表の前に「結論」「位置と問題の切り分け（直前の合意点との差、障害箇所と変更箇所、既存問題との区別、直前の返信から訂正する事実）」「主張と出どころ（確認済みと未確認の境界）」「求めること」を同じ下書きに書き出してから対応表を作る。

### 2. 7列の対応表で具体対象と役割を決める

次の7列をこの順で作る。出典を左端、候補語とその後の初出定義を右端に固定し、列順は変えない。表の行数に上限は設けない。

```markdown
| 出典 | 目的 | 具体対象 | 役割 | 前後関係 | 候補語 | 初出定義 |
```

- 本文、見出し、表の区分名、図（見出し、要素名、矢印のラベル、凡例）で、今回の対象（コード、設定、ファイル、フォルダ、パス、識別子、値・記録、状態、処理、条件、文書・節、やりとりの構成要素）やその中身・集まりを指す名詞は、日本語の一般語に見える語であってもすべて独立した1行にする。コードや記録の値（ハッシュや設定値）、ディレクトリやパス、実行主体や比較の側、別の行の具体対象の列に説明として書いた要素、図の箱や矢印に出す要素も、本文や図で指すなら最初から別行に分ける。行にしないのは、今回の対象のどの要素・値・パス・処理・集まりの代わりにもならない説明語（結果、理由、原因、手順、推測）と、名詞にせず動詞の文のまま書く箇所だけにする。
- 1行に載せる表記は1つだけにする。本文や図で別々に出す複数の対象を `/`・`・`・`、` で1行にまとめない。具体対象の列に書いた別の要素を本文や図に出すときは、その場で別行に切り出す。
- 左の5列（出典、目的、具体対象、役割、前後関係）を先に埋め、具体対象と役割が埋まるまで候補語と初出定義は空欄のままにする。左の5列に書いた語を、候補語の列で確定せずに本文や図へ直接持ち出さない。

左の5列は次の基準で書く。

- 出典：リポジトリのコード、設定、ファイルパス、コマンド、サービスやツールの原文、依頼文やユーザーの発言、公的名称、定着した専門用語やカタカナ語にある元の表記を書く。候補語に使う元の表記（所属を示す親の名前を含む）を略さず書き、「同左」「等」「など」は書かない。原文を引用するときは連続した文字列だけをそのまま写し、離れた語をつないだり省略記号で縮めたりしない。書き手が同じ会話の前の返信、前に作った表、図、作業のメモに書いた語と、ほかのエージェント（ほかのセッション、サブエージェント、ほかの AI）が書いた文にある語は出典に数えない。どこにも元の表記が無い場合は「なし」と書く。
- 目的：その具体対象を今回の返信、文書、図で何のために扱うかを書く。
- 具体対象：出典（原文、識別子、ユーザーの発言）から、確認した実際のパス、識別子、条件、実行主体と操作対象を書く。確認できていない部分は未確認と書く。書き手が自分で付けた呼び名や独自の省略語を書かない。「届く／届かない」「返る／返らない」「到達／未到達」「遅延」のように境界をまたぐ状態語を使うときは、どの部品からどの部品への到達（またはどの境界での停止）を指すかを具体対象の列に書き、役割を `状態・イベント` として登録する。同じ返信と図の中で定義を変えず、到達前の遅延と到達後の無応答のような別の事象を同じ語に混ぜない。
- 役割：`対象物`（ファイル、フォルダ、文書・節、ツール、plugin、エージェント）、`値・記録`（変数、定数、設定値、ハッシュ、本文、ログ）、`動作`（関数、処理、手順、テスト）、`条件・規則`（開始条件、対象判定、除外条件、優先順、制約）、`状態・イベント`（状態、フラグ、フック等のイベント）の5つから1つだけ選ぶ。自由記述はせず、役割の列の分類名を本文や図の表記に流用しない。同じ言葉が複数の役割（たとえば `動作` と `値・記録` や `対象物`）にまたがる場合は必ず行を分け、別々の候補語を割り当てる。
- 前後関係：推論や作業、処理の順序（例：テスト → 切り分け → 対策）があるときは、その順序を原文の言葉で書く。役割は役割の列にだけ書き、前後関係と混ぜない。

同じ文書の修正や続けて送る返信で既存の対応表を再利用するときも、既存の対応表を読み直して今回の具体対象、役割、前後関係に照合し、追加や変更がある行を具体対象から確定し直す。

### 3. 候補語と初出定義を決める

左の5列がすべて埋まり、具体対象と役割が確定してから、候補語と初出定義を次の基準で決める。

出典がある行では、候補語の列に本文や図へ実際に出す文字列そのものを書き、「同左」「原文のまま」のような指示文は書かない。出典がコードの識別子、設定名、パス、定着したカタカナ語のときは、次の3つのいずれかを選ぶ。

1. 識別子をそのまま書く。識別子だけで指せる場合、または動作や値を本文の述語で書ける場合の基本とする（例：`additionalContext`、`sha256`、`REPLY_TOOLS`）。定数に実測値を添えるときは識別子を残して括弧で添え（例：`HOLD_SECONDS`（3秒））、識別子を省いた数だけの「3秒」「7000字」は書かない。
2. 識別子に一般的な種類語または実在する親の所属名だけを添える。識別子だけでは種類や場所が伝わらない場合に使う（例：`Skill` ツール、`PreToolUse` イベント、`check.py` の `check_skills_reinvoked`、`poteto-mode` の `SKILL.md`）。添えてよいのは種類語（ツール、イベント、ファイル、フォルダ、skill、plugin、定数、関数、設定）と実在する親の出典名だけとし、中身を訳した修飾語や相対語（「返信の」「状態の」「全体の」「今の」「〜版」「〜役」）は足さない。
3. 何をするかの動詞の文にする。判定関数や処理をコード名ではなく動作や条件として書きたい場合に使う（例：`whole_read` は「`offset`・`limit` なしで全文を `Read` したかを判定する」、`permissionDecision deny` は「tool の呼び出しを止める」）。動詞を単独の名詞にした語（「差し込み」「割り当て」）や要約の呼び名（「全体の Read」「更新を知らせる見出し」）にはしない。

引用符で囲むのは原文にそのまま連続して載っている文字列だけにする。`event`（イベント）や `context`（コンテキスト）のような定着したカタカナ語を独自の日本語に訳さない。

出典が「なし」の行や複数の対象を扱う行は、次のとおり扱う。

- 出典が「なし」の行では、新しい呼び名、独自の合成語、短縮語、動詞の連用形を単独の名詞にした語を作らず、何が何をするかを動詞の文で書く。コードの識別子やファイル名など新しい名前がどうしても必要なときだけ、必要性を確認したうえで候補語を決め、初出定義の列に「X とは〜を指す」の形で出典のある定義を書く。出典のある定義を書けない語は使わず、代わりに何が何をするかの文を書く。
- 複数の物を指す行では対象の名前を省いて個数や位置だけで指さない。対象の名前をすべて並べるか、並べきれないときは対象を選ぶ条件を文で書く。
- 比べる2つ以上の物を指す行では記号や新旧のような仮の呼び名を付けず、中身の違いで書き分ける。
- 複数の手順を扱う行では1つの抽象名詞句にまとめず、行う順に動詞の文で書く。

### 4. 対応表を点検して別ファイルに保存する

保存する前に7列すべてを読み返して次の3点を点検し、問題があれば直してから下書きと対応表を保存する。

- 候補語の列を隠し、具体対象の列だけで何について述べているかが読めることを確かめる。読めなければ具体対象の列を書き直す。
- 出典の無い呼び名、識別子を省いた数だけの表記、複数の対象を1行に詰めた表記、出典や候補語の列にある「同左」「等」「など」「原文のまま」、動詞の連用形を単独の名詞にした語、1つの語が2つの役割を兼ねる表記、英語の独自訳、起点と終点の部品を書いていない境界の状態語が紛れ込んでいないか確かめる。
- 候補語の列を見比べ、同種の対象が2つ以上あるのに個別名を外した総称（plugin、skill、hook、スクリプト、設定ファイルなど）を単独で使っている行や、別の処理や状態に似た動詞（「返す」「送る」「止める」「戻す」など）を主語や対象なしで単独使用している行が無いか確かめる。衝突する行には個別名や操作対象、起点と終点を足して見分けられる表記に直す。

点検を終えたら、手順1の下書きの欄と7列の対応表を別ファイルに保存する。

- 保存先のディレクトリが無ければ先に作成し、スクラッチパッドの `referent-tables/referent-table-<slug>.md` に保存する。スクラッチパッドが無ければ `tmp/referent-tables/` に同じファイル名で保存する。
- 保存を完了してから本文と図の作成に着手する。完成した本文の先頭に対応表を置くだけでは先に保存したことにならない。
- 書き込みが禁止された環境ではファイルを作らず、同じ下書きと7列の対応表を会話の中で本文より先に確定してから書く。

### 5. 対応表に沿って本文と図を書く

- 本文や図に今回の対象を指す名詞を書く前に、「この語の出典を、原文、識別子、ユーザーの発言のどれかで埋められるか」を問う。書き手が同じ会話の前の返信、前に作った表、図、作業のメモに書いた語と、ほかのエージェント（ほかのセッション、サブエージェント、ほかの AI）が書いた文にある語は出典に数えない。埋められない語は対応表に行を作って初出定義を書き、保存し直してから本文の初出で定義を添えて使う。出典のある定義を書けない語は使わず、代わりに何が何をするかの文を書く。
- 本文、見出し、表、図で今回の対象やその値、パス、処理、集まりを指す名詞は、対応表の候補語の列に確定した表記だけを一字変えずに繰り返す。左の5列に書いた語や、対応表に無い名詞、パスの一部を切り出した呼び名、色や位置や個数だけの参照に置き換えない。値や中身を指すときも、候補語の列の識別子やパスを落とさずそのまま使う。境界の状態語を使うときも、具体対象の列で固定した起点と終点の定義を本文と図の両方で変えない。
- 執筆中や作図中に候補語の列に無い言い方が要るときは、新しい名詞句を作らず、候補語の列の表記を使った動詞の文（複数なら候補語の列の表記を並べる）で書く。どうしても今回の対象に属する別の具体対象を独立した名詞で指す必要があるときだけ対応表へ戻り、独立した行を足して7列を確定し保存してから使う。
- 図の見出し、要素名、矢印のラベル、凡例は候補語の列の表記と動詞、助詞だけで組み、対応表に無い名詞を置かない。枠に収まらない場合も語を縮めたり別の語へ言い換えたりせず、改行や要素の分割で収める。図の要素を色や位置や個数で指さない。
- 見出し、箇条書きの先頭の太字ラベル、表の区分名で内容を短い名詞にまとめない。候補語の列の表記をそのまま置くか、候補語の列の表記を使った動詞の文で書き出す。
- 本文を書き終えて送信する前に手順1の下書きと突き合わせ、下書きの各欄（結論、位置と問題の切り分け、主張と出どころ、求めること）が本文の決まった位置（1行目の結論、位置と切り分け、主張、求めること）に抜けなく入っているか確かめる。

## 問題が起きたときの対処

- 対応表を保存せずに本文や図を書き始めたことに気づいたら、後付けで対応表を足して続けず、書きかけの本文と図を破棄し、対応表を先に保存し直してから作り直す。
- 具体対象や役割の取り違えに気づいたら、本文に補足説明を足すのではなく、先に対応表の該当行を書き直して保存してから本文と図の該当箇所を書き直す。
- 保存先を作成できない場合はリポジトリのルートに代替保存せず、許可された一時ディレクトリを使う。
