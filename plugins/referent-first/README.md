# referent-first

文章やコードの識別子を書く前に、指す対象と役割と名前を確定し、決めた名前だけで書くための skill。名前を先に置いて対象を後から当てはめたり、書きながら短い呼び名や作業ラベルを作ったりして意味がずれるのを防ぐ。

## 何を防ぐか

- **不要な造語と短縮語**：既存のコード、設定、コマンド、製品の画面、用語集、ユーザーの発言にある名前をそのまま使い、勝手に作った呼び名や短縮語を導入しない。
- **作業ラベルと1語の総称**：骨組み、見出し、表の列見出し、チェックリストに「観測をまとめる」のような作業ラベルや、「作業者」「相手」「動く所」「対象」のような1語の総称を置かない。
- **同じ物の言い換えと仮の呼び名**：同じ物を返信や表をまたいで別の語に言い換えない。修正の前と後、2つの案、2つのブランチのように比べる物も「版」「新」「旧」「案A」と呼ばず、どのブランチのどのファイルか、何を変えた物かで書く。
- **他エージェントや自分のメモからの造語の引き継ぎ**：ほかのセッション、サブエージェント、ほかの AI が書いた文や、作業中に自分が書いたメモ・作業記録・結果の表にある呼び名を既存名の根拠にしない。

## 書く手順

- **返信、進捗チェックリスト、PR の説明、issue、依頼文**：書き始める前に、触れる対象と使う名前を会話の中で先にそろえ、本文、題名、見出し、表、チェックリストのすべてで同じ名前を繰り返す。
- **設計資料、調査報告、対策案、新しい名前を決めるとき**：本文より先に7列の対応表（出典、目的、具体対象、役割、前後関係、候補語、初出定義）を別ファイルか別ターンで確定し、具体対象と役割を埋めてから候補語と初出定義を決める。

## 使われる場面

`SKILL.md` の `description` には「返信、進捗チェックリスト、PR の説明、依頼文、設計資料、調査報告、対策案を書くとき」と「コードや画面の新しい名前を決めるとき」を記している。これらに該当する作業や、ユーザーが示した推論の順序を見出しやラベルにまとめるときにエージェントがこの skill を読み込む。ユーザー原文の引用、単純な機械編集、既存名だけを再利用する箇所、表現だけの推敲は対象外。

## 入れ方

Claude Code：

```sh
/plugin marketplace add u-ichi/agent-plugins
/plugin install referent-first@u-ichi
```

claude.ai、Agent Plugins に対応したツール、または skill 単体での導入手順はリポジトリの [README](../../README.md#入れ方) を参照。

## ファイル構成

```
plugin.json                                  Agent Plugins の manifest
.claude-plugin/plugin.json                   Claude Code の manifest
skills/referent-first/SKILL.md          skill の本文（基準、名前を探す先、対応表と執筆の手順）
```
